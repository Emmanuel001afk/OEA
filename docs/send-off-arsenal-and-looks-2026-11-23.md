# Send Off — arsenal, looks, and the state of host/join (2026-11-23)

This pass covers the four things still open from the last review: more weapons
and a real order to them, a visual identity per mode, the missing "heal up /
respawn" style features, and evidence for the host/join path. Everything below
is either in the source trees of `oea-engine` / `oea-games` or is a check script
that reads them.

## 1. The arsenal

The roster went from 13 to **16** entries, and every one now declares two things
the game can reason about instead of only numbers: a **family** and a **role**.

| Family | Guns |
| --- | --- |
| Pistols | Pistol, Revolver |
| SMGs | SMG |
| Rifles | Carbine, Burst rifle, Assault rifle, Marksman |
| Shotguns | Double barrel, Shotgun |
| Snipers | Sniper |
| LMGs | LMG |
| Launchers | Rocket, Guided missile, Mortar, Howitzer |
| Melee | Pan |

New in this pass:

* **Burst rifle** — 26 damage, 900 rpm, 24-round mag, three rounds per trigger
  pull. It is the mid-range answer to the LMG: tight groups without the belt.
* **Carbine** — 25 damage, 720 rpm, 25 rounds, but the fastest handling in the
  rifle family. Aim and swap it before the assault rifle is even shouldered.
* **Double barrel** — two shells of twelve pellets at 19 damage each. Two
  trigger pulls of enormous damage, then a long reload. Cheap ($700), brutal in
  a doorway, useless in the open.

Burst fire is a real mechanic, not a fire-rate trick: the trigger *queues* the
extra rounds (`Player.burstLeft`) and the normal cooldown-gated queue fires them,
so the burst respects the weapon's own rpm, stops at an empty magazine, and the
double barrel cannot spend both shells inside one frame.

Order matters as much as count. `Weapon.FAMILIES` is the canonical display
order, `Weapon.inFamily()` sorts by price, and both the front-end armory and the
in-match shop are grouped that way. `ArenaArmory` (`arena/ArenaArmory.kt`) is the
read-only presentation bridge: `all()`, `find(id)`, `melee()`, `families`,
`familyLabel()`, and a `WeaponInfo` that carries six normalised bars plus the raw
numbers.

The front-end **Armory** sheet (Loadout card) shows every gun in the families the
current weapon pool draws from, with the role line, the price and six bars. The
bars use fixed ceilings (140 damage counting pellets, 900 rpm, 260 m, 75 rounds),
not roster-relative maxima, so a bar means the same thing on every gun.

Design sheet: `tools/tripo/concepts/armory-preview.png`, generated by
`tools/tripo/preview_armory.py` **from the Kotlin** — re-run it after any balance
change and the picture follows.

The in-match shop is grouped by family too, and rows you cannot afford are
disabled and dimmed rather than tappable, which needed a small `MenuItem.disabled`
addition in the engine's menu API.

## 2. Heal up, spawn protect, and the status strip

* **Out-of-combat regen.** Eight seconds without taking damage and health creeps
  back at 2.2 HP/s — but **only to 60**. Medkits remain the only route to 100,
  which keeps healing a decision rather than a waiting game.
* **Medkit channel** is now visible in the world as well as the HUD: a turning
  green ring at the player's feet, a rising light column, and green motes.
* **Spawn shield** is drawn as a blue ring plus an on-screen countdown, so a
  player knows exactly how long they cannot be shot for.
* **The status strip** stacks healing, "Regenerating" (with a bar toward 60),
  reloading, spawn shield and the burst indicator in one column above the weapon
  slots, instead of four labels fighting over the same pixels.
* **Death drops now return the whole kit.** Previously a body dropped vests but
  silently ate helmets, medkits beyond one, and all three grenade types. Piles
  now carry a count (`Loot.count`), the pickup adds the stack up to the carry
  limit, and the label reads "Medkits x3" or "Frag x2" so the pile says what it is.

## 3. Looks

The composite shader gained a **grade** — `u_grade = (contrast, saturation,
warmth, clarity)` — applied after bloom, before the dither noise. Warmth is a
split tone: highlights lean amber, shadows lean blue, and the sign decides which
way the image is pushed. Clarity adds a little local contrast from a 4-tap blur,
which is what keeps terrain edges legible at distance without a sharpening halo.

The grade is **authored by the scene, not chosen by the player**:

* `Environment` carries `contrast/saturation/warmth/clarity`, and the presets
  (`day()`, `sunset()`, `night()`, `studio()`) each declare their own.
* `ArenaWorld.update()` moves the grade with the clock: noon is punched and
  saturated, night is cooler and softer, dusk leans into the split tone.
* Modes add a grade on top. Competitive modes get slightly more contrast and
  clarity; **Lights Out** crushes to near-neutral saturation and deep contrast;
  **Haunted** drops to 0.60 saturation with a cold push, so it reads as a
  different world rather than a tint of the same one.
* `Graphics.composite()` reads the grade from the environment of the pass it just
  rendered, and blends each parameter toward neutral by the player's
  **Colour grade** slider (`OeaEngine.settings.colourGrade`, 0–1.5) plus a
  **Vignette** switch. At 0 the render is exactly what it was before this pass.

Design sheet: `tools/tripo/concepts/grade-preview.png`, generated by
`tools/tripo/preview_grade.py`, which reproduces the shader's grade block in
Python and applies it to the same synthetic frame four ways. It is a check on the
*formula*, not a screenshot.

Two shader bugs were found and fixed while building this:

* the split-tone mix factor was `smoothstep(...) * 0.5 + 0.5 * warmth`, which
  tinted mid-grey even at `warmth = 0` and could never reach full warmth. It is
  now `clamp(smoothstep(...) + warmth, 0, 1)`.
* the grade was originally applied to every frame including ones that bypass the
  post chain; it now only runs when the scene actually went through `post`.

Also in this pass, in the world itself:

* **sprint and skydive wind streaks** — seven faint 3D lines behind the body,
  scaled by real speed (they only appear past the sprint threshold on foot, and
  hard while falling), so speed is something you see rather than only feel.

## 4. Host and join

There is no Android device in this workspace, so this is verified **in code** and
by a new check, not by a device test:

```
$ python3 tools/check-host-join.py
HOST/JOIN OK — join code round-trips, LAN + hotspot discovery wired,
host/join UI reaches a real transport, match is host-authoritative
```

`tools/check-host-join.py` asserts, from the sources:

* `LanJoinCode.encode` and `.decode` agree field for field (version, session id,
  port, address count, four-byte addresses, room name, CRC trailer), so a code
  shown by a host is decodable by a client on a different build of the same
  version;
* the LAN layer enumerates network interfaces, filters to site-local addresses,
  targets both the subnet broadcast and `255.255.255.255`, recognises
  `softap`-style hotspot interfaces and excludes `rmnet` mobile data;
* `NetSession.startLan` actually starts a `LanServer`, a `LanBeacon` and a
  `LanAdvertiser`, and produces a join code — and explains itself when there is
  no Wi-Fi or hotspot;
* every row of the "Play with friends" sheet calls a function that exists, the
  host path starts both transports (LAN and online invite), the join path
  decodes a code and calls `joinLanAny`, and join-nearby starts a `LanBrowser`;
* the match is host-authoritative: clients send commands, the host sends
  snapshots, steps the simulation and applies RTT/2 + 110 ms lag compensation to
  hit detection.

**What this cannot prove** is runtime behaviour on a real hotspot: which
interface the host binds, whether the router blocks broadcast between clients,
and mDNS quirks. Those need two phones. The static evidence says the paths exist
and line up; it does not say a specific router will cooperate.
