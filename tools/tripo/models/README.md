# Send Off — source 3D models

Committed source material, not shipped assets. The APK contains only the
converted `.oeac`; these files are here so the character can be rebuilt.

## `send-off-soldier.glb`

- **What it is:** a standing tactical soldier — helmet-cap hair, scarf, plate
  carrier with pouches, belt kit, thigh holster, gloves, boots — as one static
  mesh in an A-pose.
- **Provenance:** added in commit `f380295e` ("3d") at the repository root as
  `3d.glb`, together with `3d.fbx` and the angle-inspection sheet that was used
  to check it. Moved here unchanged.
- **Measured contents:** 4,052,696 bytes; written by `trimesh`; glTF 2.0;
  10,040 vertices, 9,594 triangles, one material, two 4096×4096 WebP textures
  (base colour and metallic-roughness, referenced through `EXT_texture_webp`).
  Y up, 1.00 unit tall, centred on the origin. Bounding box
  0.585 × 0.999 × 0.197 — the long axis is Y, so the model stands.
- **It has no rig.** No `skins`, no `JOINTS_0`, no `WEIGHTS_0`, no animations.
- **What it becomes:** `oea-engine/src/main/assets/characters/hero_rigged.oeac`,
  via `autorig.py`. Build it with:

  ```bash
  python3 tools/tripo/glb_to_oeac.py tools/tripo/models/send-off-soldier.glb \
    --out oea-engine/src/main/assets/characters/hero_rigged.oeac \
    --textures oea-engine/src/main/assets/characters/hero_rigged
  ```

- **What it is not:** a render of the shipped procedural bodies. It replaces
  the local player only; the five bots are still generated by
  `concept_to_oeac.py`.

## `send-off-soldier.fbx`

- The same mesh exported from Blender 4.5.8 ("Blender (stable FBX IO) -
  4.5.8 LTS - 5.13.1"), binary FBX 7.4.
- Also unrigged: no `Skin`, `Cluster`, `Deformer`, `LimbNode`, `BindPose` or
  `AnimationCurve` records anywhere in the file.
- Kept because it is the modeller's export and is what you would re-open to
  change the mesh. **Not read by any tool in this repository** — the pipeline
  takes the GLB. There is no FBX parser here, and adding one would be a
  day of work for a file that already exists in GLB.

## Why the inspection sheet looks wrong

`3d-glb-angle-inspection.png` shows the figure lying along Z. That is the
camera, not the mesh: the bounding box above proves the long axis is Y. It is
kept here because it is the sheet the model was checked against, and because the
mistake it contains is worth being able to look at. See
`docs/send-off-imported-soldier-rig-2026-11-24.md` §1.
